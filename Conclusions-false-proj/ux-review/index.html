UX / UI expert pass · AI Subs Player (VideoPlayerAutoSubs) · decisions recorded

The engine is ahead of the product. Let the player play first, and make the translation a quiet passenger.

The translation pipeline (Context Bible, JIT runway, express lane, disk cache) is genuinely better than what most subtitle tools do. The UI, though, is still an engineer's console: opening a video blocks on network and model work, panels hide the video, every path is a text field, and there is no keyboard, fullscreen, volume or export. The fixes below are mostly flow and structure, not new engine work.

Five moves that change the experience most

Play immediately, prepare in the background. mpv can show the first frame in under a second. Today the user waits for subtitle resolution, Ollama startup, TMDB, Wikidata and an LLM pass before anything appears. Show the video with source subtitles while the Bible builds, then swap in Hebrew as the runway fills.
One status vocabulary everywhere. Library chips, the stage pill, the transport bar and the background queue each invent their own words (100%, ready, context…, ASR 40%, queued, "% translated"). Replace with six states: Instant, Ready, Preparing, Transcribing, Translating, Needs attention.
Panels dock beside the video, never over it. Settings and the Bible currently hide mpv entirely. A right-hand panel that shrinks the stage keeps the picture visible, which also makes live subtitle editing possible.
A real player surface. Keyboard shortcuts, fullscreen, volume, audio track, subtitle mode (Hebrew / both / source / off), subtitle delay, ±10 s. These are table stakes; their absence makes the app feel like a demo.
First-run health check with fixes, not defaults pointing at one external drive. Detect mpv, ffmpeg, Ollama, the model, Whisper and the cache folder; offer a one-click fix for each. Nobody should learn about a missing binary from a failed video open.
1 · Audit

What gets in the user's way today

Severity is about impact on a person trying to watch a film, not code quality. Each finding points at the code that causes it and names the fix that the later sections assume.

Critical

Opening a video blocks playback on the whole preparation pipeline

electron/session.ts:66-190 · electron/ipc.ts:171-201

PlayerSession.open resolves subtitles, possibly runs Whisper, starts Ollama, calls TMDB and Wikidata, runs an LLM bible pass and opens the cache before player.load() is ever called. The user sees "Opening…" for 10–60 s (minutes with Whisper) even though mpv could be playing the file at once. For a player, time-to-first-frame is the single most important metric.

Split open into load (hash + mpv load, under a second) and prepare (everything else, async, cancellable). Show source subtitles or none until the runway is ready, then hot-swap the ASS track. The stage shows a small "Preparing subtitles" pill with the current step, not a full-screen wait.
Critical

Whisper transcription starts on its own with no consent, no estimate and no way out

electron/session.ts:82-93

If a file has no subtitles the app silently begins a large-v3-turbo transcription on the whole file. That can take many minutes, pins the GPU, and the only feedback is a percentage in the empty stage. The user cannot decline, cannot watch meanwhile, and cannot pick a subtitle file they already have.

A dialog with an estimate ("about 9 min for 42:10 with large-v3-turbo"), three choices: Transcribe now, Play without subtitles, Choose a subtitle file. Transcription runs in the background queue; playback starts immediately either way.
Critical

Opening Settings or the Bible makes the video disappear

src/App.tsx:69-72 · electron/ipc.ts:246

setStageVisible(false) drops mpv's on-top flag so the app window covers it. From the user's side the film vanishes and keeps playing invisibly. You cannot correct a name while looking at the scene it is wrong in.

Replace both modals with a docked right panel that shrinks the stage (the geometry reporting in MpvStage already handles resize). Settings gets its own window or a docked panel too. Nothing ever overlays the picture until the app is single-window.
Critical

No first run. Defaults hardcode one external drive; failures surface only on open

electron/engine/types.ts:153-179 · electron/ipc.ts:79

Models, Whisper, cache and the binary paths default to /Volumes/EP2TB/StoryBookProject/…. Ollama status is a nine-pixel dot. mpv missing is reported after the user clicked a film. Nothing tells the user what is installed, what is missing, or how to fix it.

A setup screen that runs on first launch and from Help → Check setup: detect mpv, ffmpeg/ffprobe, Ollama, the default model (offer the pull, which ollamaPull and the progress event already support), Whisper (optional), TMDB key (optional), storage folder. Each row has a status and a fix button. Defaults become the app's own support folder; the external drive is a choice the user makes with a folder picker.
High

No keyboard control at all

electron/player/mpv.ts:66 (--no-input-default-bindings) · src/ (no key handlers)

mpv's default bindings are disabled on purpose (correct, the renderer should own input) but the renderer never registers any. Space does nothing. Arrow keys do nothing. Escape does nothing. Every player the user has ever used trained them otherwise.

One keymap owned by the renderer, forwarded to mpv over IPC. See the keyboard table in the UI system section.
High

Missing fullscreen, volume, audio track and subtitle mode

src/player/TransportBar.tsx · electron/api-contract.ts:58-63

The transport offers play/pause, a scrubber, and a speed select. mpv exposes fullscreen, volume, mute, aid, sid, sub-delay and sub-visibility; none are wired. A film with an English and a commentary track cannot be switched. Subtitles cannot be turned off.

Extend the contract with setVolume, setMute, setFullscreen, setAudioTrack, setSubMode, setSubDelay, plus a tracks query on load. Surface them in the transport and in a Subtitles menu.
High

Only "open a folder"; no single file, no drag and drop, no recents

src/library/LibraryPanel.tsx:54-57 · electron/ipc.ts:161-166

The most common desktop action, double-click a file or drop it on the window, is impossible. Library state is also lost on relaunch: the folder must be picked again every time.

File → Open File (⌘O) and Open Folder (⇧⌘O), drop target on the whole window, persisted library folders, Continue watching, Open Recent, and registering the app as a handler for video extensions.
High

The translated subtitles can never leave the app

electron/scheduler/cache.ts · electron/player/ass.ts

After a 100% pre-translation the Hebrew lines live only in the cache JSON and a temporary ASS file. The sibling Ivrit Subs app exists precisely to write movie.he.srt; this app has the same data and no export.

File → Export Subtitles (SRT / VTT / ASS), a context-menu action on library rows, and an optional setting "write a sidecar .he.srt next to the video when a title reaches 100%".
High

Correcting one character throws away the whole translation cache

electron/bible.ts:26-28 · electron/scheduler/cache.ts:44-70 · src/panels/BibleInspector.tsx:86

The cache header stores bibleHash; on mismatch TranslationCache.open starts fresh. So fixing "Sarah → female" after a full pre-translation discards every line, silently, on next open. The inspector's tooltip "Saved for the next time this title is opened" hides this. The README lists live re-translation as a planned enhancement; the cache design makes it urgent.

Keep the cache; store the bible hash per cue instead of per file. On save, re-translate only cues whose text mentions the changed character or term (aliases included), live, with a panel footer showing "Re-translating 12 lines…".
High

Paths are free-text inputs with no picker, validation or test

src/panels/SettingsPanel.tsx:134-199

Whisper binary, models dir, mpv binary, cache root, models dir: five path fields the user has to type. A typo is discovered when a video fails to open. The "Ollama host" field accepts anything.

Every path gets a Browse button (Electron's open dialog), a detected-or-not indicator, and where meaningful a Test button (mpv --version, whisper-cli -h, Ollama ping). Ollama's host and managed-server toggle belong on an Engines page with a live status row.
High

Three vocabularies for one thing, and "Bible" is engine jargon

src/library/LibraryPanel.tsx:16-35 · src/player/TransportBar.tsx:76 · src/App.tsx:130

The same title can read "100%", "ready", "context…", "ASR 40%", "queued" and "43% translated" depending on which surface you look at. The top bar says "Bible (7)", which means nothing to a viewer. "JIT", "ASR", "coverage" and "lookahead" also leak into labels.

Six user-facing states (Instant · Ready · Preparing · Transcribing · Translating · Needs attention) rendered by one StatusChip component fed by one merged status per path. Rename Bible → "Cast & terms", coverage → "translated", ASR → "transcribing", lookahead → "translate ahead".
High

Settings mix viewer choices with engine tuning on one screen

src/panels/SettingsPanel.tsx

Target language sits next to concurrency and batch size; subtitle size next to hwdec. Seven of the twenty-one fields in AppSettings (numCtx, temperature, recentPairs, contextWindow, behindKeepMs, numParallel, manageServer) are not exposed at all, while the ones that are exposed have no explanation of consequences.

Pages: General, Subtitles, Translation, Engines, Metadata, Storage, Advanced. Translation gets a Fast / Balanced / Quality preset that sets model, batch size, concurrency and context together; the raw knobs live under Advanced with one-line consequences ("Larger batches: fewer requests, slower first line").
Medium

No resume position, no watched state

electron/ipc.ts:187-197 (lastPosMs reset to 0)

Closing and reopening an episode starts from zero. The translation cache remembers everything; the player remembers nothing.

Persist position per video hash on pause/close/every 10 s. Library shows a progress bar on the row and a "Continue watching" strip. Auto-advance to the next episode at the end of a series file.
Medium

Errors are one-word chips or a red string in the stage

src/App.tsx:101-106, 151 · src/library/LibraryPanel.tsx:20

"error" on a library row has no detail and no action. mpv start failure is a sentence in the stage. TMDB failures (bad key, offline) are invisible: the bible quietly gets confidence "low".

The "Needs attention" state opens a small popover with the message and an action (Open setup, Retry, Choose subtitle file). Non-fatal degradations (no TMDB) show once as a toast and once in the Cast & terms panel header.
Medium

Scrubber shows runway but there is no legend and no seek preview

src/player/TransportBar.tsx:53-59

The faint blue "ahead" segment is the app's most interesting idea and nobody can tell what it means. Cached regions elsewhere in the file are not shown, so the user cannot see where seeking will be instant.

Three-tone bar: played, translated (any cached region), not yet translated. A timecode tooltip on hover. The transport's "43% translated" moves into the Subtitles menu; the bar itself is the indicator.
Medium

No subtitle delay, and style changes require a reopen

electron/player/sub-feeder.ts:46-52 · src/panels/SettingsPanel.tsx:161-176

Sidecar and Whisper subtitles are frequently off by a few hundred milliseconds. mpv has sub-delay. Font size and outline are numbers in a modal with no preview and take effect only on the next session.

Subtitles menu: delay −/+ 100 ms (, .), size −/+, position. Settings → Subtitles shows a live preview strip and pushes sub-font-size/sub-border-size to mpv immediately.
Medium

Pre-translation is all-or-nothing and un-orderable

src/App.tsx:87-90 · electron/background.ts:48-60

"Pre-translate library" enqueues every file. You cannot queue one season, cancel one item, or move tonight's episode to the front. The "Translate all" button in the top bar duplicates this for the open file.

Per-row and per-title context menu: Translate now, Move to front, Remove from queue. A Queue view (small panel or the sidebar footer) lists what is running and what is next, with an estimate.
Medium

The library sidebar cannot be hidden while watching

src/index.css:74-77

A fixed 300 px column stays beside the film. In a 1200 px window that is a quarter of the width lost to a list you are not using.

Sidebar toggles with ⌘1 and collapses automatically in fullscreen and after 5 s of playback if the user chose "auto-hide library while playing".
Medium

No completion notification, and the Mac can sleep mid-film

electron/background.ts · electron/main.ts

A 2-hour background pre-translation finishes silently. Electron does not stop the display from sleeping while mpv plays in a separate window.

powerSaveBlocker.start('prevent-display-sleep') while playing; a macOS notification "Season 2 is ready to watch" when the queue drains; the dock badge shows the number of running items.
Medium

Source language is assumed English; target is global only

electron/engine/media.ts:81 · electron/engine/types.ts:130

Embedded track selection prefers "eng"; Whisper is not told a language. A French film with French subs would be translated as if English. Changing target language is a global setting that invalidates every cache key.

Detect the source language from the track tag or the first 50 cues, show it in the Subtitles menu, allow override. Target language: global default plus a per-title override in the same menu.
Low

Emoji as icons

src/App.tsx:139 · src/library/LibraryPanel.tsx:66 · src/player/TransportBar.tsx:69

⚙, ⚡, ⏸, ▶, ❚❚ render differently per OS and font, cannot be recoloured for states, and read as placeholder.

One inline SVG icon set (Lucide is MIT, tree-shakable, and has every glyph the player needs).
Low

Product name and brand line

package.json:3 · src/library/LibraryPanel.tsx:50-53

"VideoPlayerAutoSubs — on-demand subtitle localization" describes the repo, not a product. It also takes 40 px of the sidebar permanently.

Pick a name (decision D10). The sidebar header becomes the folder switcher; the name lives in the About box and the dock.
2 · New user flow

From launch to Hebrew on screen in three clicks

The principle: every long operation runs behind a playing video, and the app only interrupts when it needs a decision (no subtitles found) or a fix (something missing). Steps are in the order a first-time user meets them; returning users start at step 3.

Goal

The user never discovers a missing dependency by failing to open a film.

What happens

On first launch (or when a required check fails at launch) the Setup screen lists mpv, ffmpeg, Ollama, the translation model, Whisper, TMDB key and storage. Required rows block "Start watching"; optional rows do not. Each row has a fix: Locate…, Download (with progress), Paste key + Test, Choose folder. The Ollama row starts the managed server itself.

Exit

All required rows green → Library. Setup stays reachable from Help → Check setup.

Goal

Getting a file in takes the same gesture as in any Mac app.

What happens

Drop a file or folder anywhere on the window. ⌘O opens a file; ⇧⌘O adds a folder. Folders persist and rescan on launch and on a "Rescan" action. A dropped single file plays immediately and is added to a "Loose files" group. The app registers as an "Open with" target for mkv/mp4/mov.

Exit

File → plays. Folder → Library.

Goal

Decide what to watch in five seconds, and know whether it will be instant.

What happens

Continue watching strip on top (posters from the Bible metadata when available, progress bar). Below, titles grouped as series/movies with one chip per file: Instant (cached), Ready (subs found, will translate live), Needs transcription (no subs), Translating 43%, Needs attention. Search box filters. Right-click gives Translate now, Move to front, Export subtitles, Rebuild context, Reveal in Finder. The queue footer shows what is running with an estimate.

Exit

Double-click or Enter plays.

Goal

First frame in under a second, every time.

What happens

mpv loads the file at once with the embedded/sidecar subtitle track selected (if any) so the user has something to read. A pill in the top-left of the stage shows the prep step: Finding subtitles → Building context (TMDB · Wikidata · reading dialogue) → Translating ahead. When the runway covers the playhead + 10 s, the translated ASS track replaces the source track with no interruption. If a cache exists, the swap is immediate and the pill never shows.

Exit

Pill disappears; scrub bar shows the translated region growing ahead.

Goal

Never spend nine minutes of GPU without asking, and never leave the user stuck.

What happens

Video is already playing without subtitles. The app first queries OpenSubtitles (and Subdl as a second source) by file hash and by title. A dialog then offers, in order: Download what was found online (a hash-matched Hebrew file is preferred and becomes the default track; an English match becomes the translation source), Transcribe now (estimate from duration × the measured speed of this Mac, e.g. "about 9 min"), Choose a subtitle file, Play without subtitles. Transcription runs in the background queue; the pill shows progress; Hebrew appears when done. For series, one checkbox applies the choice to the whole season.

Decided (D3, D3b)

Ask each time with an estimate, with online search offered for every file, not only as a fallback. A hash-matched online Hebrew file wins over the app's own translation by default; the translation stays one click away in the Subtitles menu.

Exit

Back to step 4 with the new source.

Goal

Feel like a real player; translation state is visible but never in the way.

What happens

Controls appear on hover / mouse move and hide after 2.5 s (below the stage until single-window, then overlaid). Space, arrows, F, M, ±10 s, volume, audio track, Subtitles menu (Hebrew / Hebrew + English / English / Off, delay, size), speed. The scrub bar shows played / translated / not yet translated. If the runway is about to run dry (rare, e.g. 2× speed on a cold file) a quiet pill says "Translating ahead…" and the source line shows in place of the missing Hebrew line rather than nothing.

Exit

End of file → next episode prompt (auto after 10 s if enabled).

Goal

Fixing a wrong name or a bad line takes seconds and applies now, not next time.

What happens

The right panel has two tabs. Subtitles: the cue list synced to the playhead; click a row to seek; edit a Hebrew line inline; "Retranslate" with an optional hint ("she is speaking to a man"). Cast & terms: names, Hebrew rendering, gender with its source (Wikidata / cast / model / you), terms; Save shows "Re-translating 12 affected lines" and the cache is kept. File → Export Subtitles writes Title.he.srt; an optional setting writes it automatically at 100%.

Exit

Edits persist in the Bible and cache for every future viewing.

Rules the whole app follows

Nothing covers the picture. Panels dock, dialogs pause, toasts sit outside the stage.
Every operation longer than 2 s shows what step it is on, an estimate when one exists, and a way to cancel.
Every path is picked, detected and testable. Every failure names the fix.
Labels say what the viewer gets ("translate ahead: 50 s"), not what the engine does ("lookahead ms").
Defaults work on a fresh Mac with mpv and Ollama installed. The external drive is a choice, not an assumption.
Corrections apply now and are kept forever. No "next time you open this".

mpv glue. Do not make that call silently.

fix what it finds, then commit and push. Commit messages describe the change and its
reason, one commit per task, no model names in the message. Do not open a pull request
unless I ask.

Report to me at each phase boundary and at every gate. Between those points, keep going
without asking permission for work the plan already specifies.

For one task at a time, the short form is: "Implement task 2.2 from the orchestration doc, delegate it to a general-purpose subagent on the opus model, build must pass before you report done." The model assignment does not change when phases are run separately.

What changes in the port

No subagents. Codex runs one agent per process, so each task becomes a codex exec invocation with its own model, and parallel work uses real git worktrees and concurrent processes instead of parallel subagents.
Instructions move into AGENTS.md, which Codex loads automatically. The decisions, build commands and conventions are inherited by every task instead of restated in a long orchestrator prompt.
Effort is a config key. model_reasoning_effort takes minimal through xhigh. The two hard tasks run at xhigh; mechanical tasks run at low and save real money.
The gate is manual. Codex will not stop and ask at a phase boundary, so the driver script stops after the spike and after each phase and waits for you.
