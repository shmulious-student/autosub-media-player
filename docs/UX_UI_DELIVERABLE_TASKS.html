Cross-cutting: Bidi & Design-System compliance

The blueprint's Golden Bidi Rules apply to every task above. Budget this once, not per feature.

Bidi audit pass +12%

  • Chrome and rail stay LTR under a Hebrew locale.
  • Transport bar and scrubber never mirror — time flows left-to-right.
  • Subtitle overlay gets RLM / bidi embedding markers.
  • Editor fields: punctuation on the logical left, Latin names in ⁦…⁩ isolates.
  • Bible name pairs: English LTR isolate + Hebrew RTL isolate.

Existing helper: lib/ui/bidi.dart — the audit is mostly call-site coverage, not new code.

Token conformance +6%

  • New surfaces pull from lib/ui/tokens.dart, no hardcoded colours.
  • Status colours resolve through entry_status.dart.
  • Radii / shadows match DESIGN_SYSTEM §3.

Cheapest as a final sweep per sprint rather than a standalone task.

Recommended sequencing. Run one sprint per window and stop at the sprint boundary — starting Sprint 3's waveform work with 20% of a window left means paying the exploration cost twice. Within a window, front-load the cheap tasks (T‑03, T‑01, T‑06) so a partial window still ships something. The two tasks worth reconsidering on cost-to-value are T‑07 (hover lexicon — 26% for a feature no other task depends on) and T‑28 (Devices Dock — the transport already works headlessly).
